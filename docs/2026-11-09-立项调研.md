## 0 结论先行

**名字：虫珀 · 蝉蜕**（包名 `@zhuifengqug/dsh-cicada`）

**方向：人格即契约** —— 把"我是谁、怎么说话、什么必须始终成立"写成可版本化的槽位契约，每轮编译成前缀段注入，出口做口径体检，换代时旧壳归档成"蜕"、可回滚。

三条与市场错位的判断：

1. 市场在**注入**上已经饱和（69 条里 40+ 条本质都是"往系统提示里塞一段人"),但在**守门**上几乎空白：只有 `dsh-persona-framework` 一个做了出口自检，且它明说"只给框架，不含人格"。
2. 市场普遍把**人格、记忆、偏好**焊在一个文件里（改一条记忆等于改一次人格），而我们已有的 `USER.md / MEMORY.md / AGENTS.md` 是现成的事实源——人格应当只**引用**它们，不复制。
3. 只有 `dsh-catgirl-plugin` 量化过人格的 token 成本（-67% 输入、-66% 缓存读）。人格段是每轮都在的前缀，成本必须一等领域对待。

## 2 七个共性坑（都能在 README 里找到证据）

1. **token 税无人核算**：人格段是每轮前缀，69 条里只有 catgirl 给出数字，其余把长人格当免费。
2. **人格漂移无人管**：只有 persona-framework 有"出口自检"；其余全部靠"每轮注入就等于执行"。
3. **人格≠记忆≠偏好 三者混淆**：把偏好写进人设、把记忆写进规则，改一条记忆等于改一次人格，无法单独审。
4. **双真相源**：人格文件 + 插件内部状态（面板）各存一份，冲突时不知道听谁的（anima / soul-desk 都以面板为主编辑口）。
5. **覆盖式重写 vs 追加**：distill 每周覆盖（丢历史），soul 走 git（可回滚）——两条路不可兼得，市场没给出选择依据。
6. **与宿主对赌**：yuike / jailbreak 走"替换整份系统提示"，宿主一升级就失效；只有拒斧那套"逐条可回滚"是对的姿势。
7. **作用域只有一级**：三级（全局 / 工作区 / 会话）只有 anima 做了两级，会话卡（persona / persona-L）另起一套，互不兼容。

## 3 差异化空位

一句话：**没有人在做"人格的契约 + 体检 + 蜕壳归档"三件合一，并让事实源留在宿主既有文件里。**

| 能力 | 市场现状 | 蝉蜕要做的 |
|---|---|---|
| 声明形态 | Markdown 散文 / 面板表单 | **槽位契约**（身份·称呼·语言·语气·边界·禁区·技能路由），逐槽可 diff |
| 注入 | 整段塞入 | **编译**：稳定核 + 可变层分块，每块带 token 预算，保缓存稳定 |
| 版本 | 无 / 覆盖重写 / git 提交 | **蜕**：每次换代产出一枚蜕（快照 + 差异），可回滚到任意一枚 |
| 守门 | 基本无 | **体检**：称呼/语言/语气/边界四类漂移信号，写文件前与会话末尾两处可跑 |
| 事实源 | 插件自己存 | **只引用** USER.md / MEMORY.md / AGENTS.md，不复制、不接管 |
| 作用域 | 一级或两套不兼容 | 全局 → 工作区 → 会话 三级，明确覆盖与优先级 |

## 4 三案对比

- **A 人格契约 + 体检（推荐）**：定位"人格的可执行契约与守门人"。市场空白明确，工程量可控（注入 + 档案 + 体检三块），且与已有的 mnemon（记忆）、billion-context（压缩）、Aegis（方法）、玄驹（团队）互补不重叠。
- **B 多角色壳库**：市场已拥挤（persona / persona-L / soul-desk / anima / amadeus 五家），差异化只剩 UI。
- **C 记忆长人格（成长）**：拥挤，且与已装的 `dsh-mnemon` 直接冲突——等于重造一个我们已经有的东西。

## 5 命名

家族既有三件：**玄驹**（蚁）、**蜻蛉**（蜻蜓）、**拒斧**（螳螂）——古称虫名 + 一个动作/身份意象 + `@zhuifengqug/dsh-<英文虫名>`。

**首选：蝉蜕（dsh-cicada）**
- 蝉蜕是"褪下来的壳"本身，不是虫子：正好对应插件交付物——**人格是壳，模型是本体**。
- 与"虫珀"同义域：虫珀封住历史，蝉蜕留下旧壳；一蜕一档，语义天然对齐。
- 生命周期自带动词：**蜕**（换代）、**留蜕**（归档）、**回蜕**（回滚），GLOSSARY 不用另造词。
- 检索无冲突：全库 `蜕` 命中 0，`蝉`/`cicada` 仅 2 条无关项（`bamboo-cicada-3d`、一张貂蝉角色卡）。

备选：**螵蛸**（螳螂卵鞘，一鞘多子=多角色包，但与拒斧同科、易混）、**蝜蝂**（柳宗元"善负"之虫，记忆负重意象，但偏贬义）。

### GLOSSARY 草案（沿用玄驹的"业务语义 + 避免词"体例）

- **蜕**：人格的一次完整版本快照，含差异与时间戳，可回滚。_避免_：备份、快照文件
- **契约**：人格的唯一声明，由若干槽组成。_避免_：人格提示词、人设配置
- **槽**：契约中的一段（身份 / 称呼 / 语言 / 语气 / 边界 / 禁区 / 技能路由），独立可 diff。_避免_：段落、小节
- **编译**：把契约渲染成每轮前缀段的过程，分稳定核与可变层。_避免_：拼接、模板渲染
- **体检**：对输出口径做漂移检测，输出信号而非判决。_避免_：自评、打分
- **事实源**：USER.md / AGENTS.md 等宿主既有文件；契约只引用，不复制。_避免_：记忆库、用户档案
- **蜕壳**：一次人格换代：新契约生效 + 旧壳归档为一枚蜕。_避免_：更新、发布

## 6 M0 范围（本轮不动代码）

1. 契约 v0 schema：七个槽的字段与渲染规则（先写死，不做 DSL）。
2. 编译管线：稳定核 + 可变层的分块与 token 预算；给出"同一契约两次编译字节一致"的缓存前提。
3. 蜕：每次落盘前产出快照与差异，支持回滚；不接管 git。
4. 体检：四类信号（称呼错、语言错、语气漂移、边界越界），先做可解释的规则 + 采样，不做模型自评。
5. 设置页：当前壳、槽编辑、蜕列表、体检记录。
6. 边界：不替换宿主系统提示（那是拒斧的活），不改写 `@deepseek-ai` 包。

### 三个动作

- **编译**：稳定核 + 可变层分块，各带 token 预算；同一契约两次编译字节一致（保 prefix cache）。
- **蜕**：每次落盘前产出快照 + 差异，编号 `#N`，可回滚；不接管 git，只维护自己的蜕目录。
- **体检**：四类信号——称呼错 / 语言错 / 语气漂移（寒暄、免责、hedging）/ 边界越界（拒绝句式、未执行的"已完成"宣称）；写文件前与会话末尾两个跑点；输出信号 + 证据句，不自动改契约。

### M0 不做

不替换宿主提示、不改写 `@deepseek-ai` 包、不做 DSL、不做多角色库、不接管记忆（记忆仍归 mnemon，契约只引用 USER.md / AGENTS.md）。

## 附录 C · GitHub 一手机制（2026-11-09 读 README，非市场页转述）

市场详情页只给宣传语，以下是从各仓库 README 挖到的可复用实现事实。

### C1 注入的两条官方路径
- `@deepseek-ai/dsh-persona` 官方插件的 config 只有 `prefix / suffix / complete / includeRuntimeContext`，**全是静态字符串**，改人格要动 profile patch 并重启（dsh-plugin-soul README）。
- `dsh-system-prompt` 的 `section.text` 支持**函数**，每次 assembly 求值 → 每轮重读文件，改 Markdown 立刻生效不重启。soul 就吃这个口子。
- `dsh-assistant-profile` 用 `deployment:persona-prefix` 注册在 **agent 自己的作用域**，作用域链最近同名段胜出 → 标准/PTC/极简/创造四模式通用，工具与流程语义不动；极简模式镜像 `complete: true`；**子智能体不注入**。这也是官方 `dsh-subagent` 的 `applyChildComposition` 给子代理发人格的同一条路。
- 记忆段 `memory:assistant` order 500，排在人格（0）之后、工具目录（1000）之前。

### C2 缓存语义（assistant-profile README 实测）
DeepSeek 是前缀缓存：人格文本每次组装求值，保存后下一请求即变，**历史一个字节不动**。模型路由声明 `systemPromptUpdate: 'in-history'`（DSH 默认 deepseek-flash 条目）时，变化的系统提示追加在已缓存历史之后，只有新增小段按普通输入计费。

### C3 成本结论（catgirl README 实测，2026-08-14 真实 API）
传统长 persona **更费**（+5%）；极短 persona ≈ 基线；真正的省钱引擎是工具 schema 裁剪（25→8，`ctx.tools.restrict()`），不是人格。人格风味可做**本地渲染 0 LLM token**，会话日志存原文。
推论：小蛛要区分**行为层**（必须进提示）与**风味层**（可 0 token 本地渲染）。

### C4 自改权限的三档现实做法
- `dsh-plugin-soul`：RULES 只读；单次 ≤800 字符、每日 ≤3 次、`why` 必填；每次落 git + CHANGELOG，`soul_rollback` 可退。升格规则：日笔记不注入，被 `soul_recall` 命中 **≥3 次**才够格，按主题 key 聚合（否则换个措辞就成新候选）。人类评分只加权不设闸门。
- `dsh-anima`：候选 → 待审缓冲区 → **用户裁决才生效**；刻意不做长期记忆自动写入。
- `dsh-mem-weave`：AI 只能写记忆提建议，改人格/规则/冲突/永久删除只能人做；24h 内一键撤销 + 审计。

### C5 质检的必要形态（anima README 原话）
「自检」如果只写在提示词里就变成新的表演面——模型会输出「已检查，无异常」，而那句话本身没有成本。所以质检判词由**代码**出，且代码只能判**形状**（有没有来源、有没有对账块），判不了内容对不对。anima 十二条判据，抓到就往下一条消息插提醒；刻意不支持「质检通过了」这类结论。
`dsh-persona-framework` 的漂移模块（gradient）只报数不拉回：四项指标跟自己的基线比，掉三成报嫌疑，不当人格检察官。

### C6 framework 的硬线（可借鉴为设计约束）
不代填、不覆盖（人格文件与框架文件路径分开写入分开）、不立法、不记忆、并列不是上下级；人格与框架冲突以人格为准。
注入分段顺序：即时 10 → 人格 20/22 → 长期 23 → 短期 25 → 其他 30。

### C7 已知的宿主坑（assistant-profile 实测）
Volatile 只暴露 `get()`，写配置必须 `settings.update(ns, patch)`；写回要 `setTimeout(0)` 挪出 `hmr.runExclusive`，否则 `HMR transactions cannot be nested`；设置写入不触发 `loader/volatile-update`，信箱靠 700ms 轮询。插件目录解析不到 `@deepseek-ai/dsh-tools` 等包，工具定义按官方线上形状手搭。

### C8 persona-shell 的隔离做法
汇报提交后**单独调模型**换口吻，人格版不写回工作会话（下一步干活的助手读到的仍是原文）；代码/路径/命令先打码再回填；失败、超时、校验失败一律显示原文。
